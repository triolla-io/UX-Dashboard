# Dashboard Screenshot Feedback Tool — Design Spec
**Date:** 2026-06-08  
**Author:** Ariel / Triolla  
**Status:** Approved

---

## Overview

An internal tool that lets users upload a dashboard screenshot and receive structured UX/design feedback as a downloadable TXT file. Feedback is generated by an AI agent via OpenRouter, guided by a pre-built `dashboard.md` skill injected as the system prompt.

## Architecture

### Data Flow

1. Browser POSTs `{ image: base64, mediaType, context }` to `/api/feedback`
2. Express reads `skills/dashboard.md` at request time, calls OpenRouter with system prompt + image
3. Returns `{ feedback: string }` — client displays it and enables TXT download

### Dev vs Production

- **Dev:** Vite dev server (port 5173) proxies `/api/*` to Express on `localhost:3001`
- **Production:** Express serves the Vite build from `frontend/dist` on a single port

## Frontend

### State Machine

`App.tsx` holds a single `view` state: `upload | loading | result`. No routing — conditional rendering only.

### Components

**UploadScreen**
- `FileDropzone`: drag-and-drop or click-to-browse; accepts PNG, JPG, WEBP; max 10MB
- `ContextInput`: free-text field, max 200 chars, placeholder: "Describe the dashboard or its context (optional)"
- `SubmitButton`: disabled until a valid file is selected
- Client-side validation on file select (type + size) with inline error display

**LoadingScreen**
- Spinner + "Analyzing your dashboard…" message
- No cancel button (v1)

**ResultScreen**
- Scrollable panel showing feedback text
- "Download TXT" button → triggers browser download as `dashboard-feedback-[timestamp].txt`
- "Start Over" button → resets state to upload view

### Error Handling (Frontend)

| Scenario | Location | Message |
|---|---|---|
| Wrong file type | Under dropzone | "Please upload a PNG, JPG, or WEBP image." |
| File too large | Under dropzone | "File is too large. Max size is 10MB." |
| API timeout | Result panel | "The analysis took too long. Please try again." |
| API error | Result panel | "Something went wrong. Please try again later." |

API errors replace the result panel and include a "Start Over" button.

## Backend

### Route: `POST /api/feedback`

**Request body:**
```json
{
  "image": "<base64 string>",
  "mediaType": "image/png",
  "context": "optional free text"
}
```

**Response (200):**
```json
{ "feedback": "string" }
```

**Response (error):**
```json
{ "error": "string" }
```

### Handler Logic

1. Validate request body — `image` (required string), `mediaType` (png/jpg/webp), `context` (optional, truncated to 200 chars)
2. Read `skills/dashboard.md` from filesystem at request time (no caching in v1)
3. Call OpenRouter `/chat/completions`:
   - `model`: value of `OPENROUTER_MODEL` env var (default: `anthropic/claude-sonnet-4-6`)
   - `system`: content of `dashboard.md`
   - `messages`: user message with `image_url` block (data URI) + text block
4. 60s timeout — return 504 `{ error: "..." }` on timeout
5. Return `{ feedback: string }` on success, `{ error: string }` on any failure

### Environment Variables

```
OPENROUTER_API_KEY=          # required
OPENROUTER_MODEL=anthropic/claude-sonnet-4-6   # optional override
PORT=3001
```

### Security

`dashboard.md` is read server-side only and never exposed to the client.

## Out of Scope (v1)

- Multi-image upload
- Async processing / job queue
- Feedback history or storage
- User accounts or authentication
- Mobile support
- Rate limiting
- Skill selector
